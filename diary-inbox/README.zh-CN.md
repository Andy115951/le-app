# Diary Inbox · 留一句

[English](./README.md) | 简体中文

安卓和电脑浏览器上的本地日记。离线随手写一句，每台设备各自保留加密的 SQLite 副本，等电脑开机再交换条目。不需要云端账号、托管数据库、统计服务或 AI 服务。

## 启动

使用 Node.js 22.13 或更高版本，在本目录独立安装依赖，不使用仓库根目录的依赖。

```sh
npm ci
npm run build:web
npm run desktop
```

在电脑打开 `http://127.0.0.1:47831`。浏览器是本机 Node.js 进程的界面，不负责保存数据。SQLite 位于操作系统的本地应用数据目录下的 `diary-inbox` 中。可用 `DIARY_DATA_DIR` 指向自己控制的目录，切勿指向仓库中会被跟踪的文件。

安卓开发需安装 Java、Android SDK，连接开发手机或启动模拟器后执行：

```sh
npm run android
```

该命令生成已忽略的安卓原生目录并运行本地开发构建。`npm start` 为已安装的开发客户端运行 Metro。第一版暂未包含独立发布 APK 和签名流程。Metro 是开发工具，不是日记同步服务器。安装后的应用把记录离线保存在自身的 SQLite 数据库中。

## 连接设备

1. **只在一台设备创建**日记本，使用至少 12 个字符的独立长口令。没有口令找回或重置功能。
2. 导出加密 `.diary` 备份，在另一台空白设备导入并用相同口令解锁。不要分别创建两本日记后再合并。
3. 也可用 `npm run desktop:lan` 启动电脑服务，打开本机界面并解锁，在「设备与备份」生成有效期五分钟的二维码。空白安卓端扫码后输入原日记本口令，验证通过才写入本机。
4. 两端连接同一 Wi-Fi，在电脑生成新二维码并在安卓扫码同步。电脑防火墙应在可信专用网络中允许 47831 端口。二维码包含临时密钥，请勿转发；电脑有多个地址时，选与手机同网段的地址。
5. 安卓完成同步后，在电脑点击「刷新电脑收到的日记」。之后电脑再修改，需要手机再次同步。本版没有后台发现或自动连接。

默认服务仅监听本机回环地址。局域网模式只开放加密同步接口；界面、SQLite 接口、会话初始化和配对控制仍限本机，并校验 Host 与 Origin。请勿公开部署、通过公网代理转发或做端口映射。空白电脑可先导入手机创建的加密备份，再解锁并生成配对码。

## 日常使用

- 输入停顿 900 毫秒后自动保存。关闭设备前主动保存并检查状态提示；未保存的草稿无法抵抗强制结束或断电。
- 每条记录都有独立日期与编号，同一天可以写多条。漏写的日子不形成待办。
- 修改作为不可变版本保留；同步交换完整加密版本历史，按编号合并，不复制覆盖 SQLite 文件。两端同时编辑会保留多个版本，选择后进入编辑器，点击保存才完成合并。删除使用保留的删除标记；另一端离线修改已删除记录时会产生冲突。
- 安卓切至后台会先保存再锁定，文件选择或分享操作完成后才锁定。电脑五分钟无点击或键盘活动后锁定。暂不提供生物识别解锁、防截屏或安全键盘保证。
- 定期独立保存加密备份。删除也会同步，同步不等于备份。旧版本会保留，暂不压缩历史或彻底清除；单设备上限为两万个版本、16 MB 序列化日记本。同步传输完整历史，第一版面向纯文字个人日记。
- Markdown 是**明文导出**，需要确认，内容包含日期标题与分隔线，供 eDiary 手动导入。日期识别和导入行为取决于 eDiary 版本；暂不支持自动导入、反向同步、EDF 解析和附件。请在 eDiary 检查导入结果后再视为已归档。

## 隐私与协议

日期、正文、修改时间和删除标记在写入 SQLite 前用 AES-256-GCM 加密，使用独立随机的 96 位 nonce，并把版本元数据绑定到认证附加数据。口令通过 PBKDF2-HMAC-SHA256、60 万次迭代和随机 256 位盐派生 256 位密钥，不保存、不传输口令。随机日记本编号、版本编号、父版本关联、历史大小及派生盐可见。不防护操作系统失陷或不可信的应用／浏览器代码；应用协议尚未经独立安全审计。

配对通过扫码或复制传递随机 256 位密钥。局域网 HTTP 请求和响应另用 AES-GCM 封装，请求与响应采用不同认证附加数据，网络请求头不传配对密钥。响应绑定随机请求编号，电脑在配对窗口中拒绝重放。五分钟后配对失效，也可在界面主动关闭。流量大小和网络地址仍然可见。安卓允许 HTTP，用于承载应用层加密的局域网消息；配对只接受私有 IPv4／回环地址，不跟随重定向、不接受外部主机。配对授权对方合并加密历史，请像保管钥匙一样保护二维码。

核心使用 [Noble Ciphers](https://github.com/paulmillr/noble-ciphers) 与 [Noble Hashes](https://github.com/paulmillr/noble-hashes)。安卓使用 [Expo SQLite](https://docs.expo.dev/versions/latest/sdk/sqlite/)，电脑使用 Node.js SQLite。没有从仓库其他应用导入代码或记录。测试只使用合成数据。数据库、备份、导出、配对二维码截图、原生构建和签名材料均不得跟踪提交。
