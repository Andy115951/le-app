# Ledger：第一版开发方案

[English](./README.md) | 简体中文

状态：已根据确认的五页草稿开始实现 Android 本地版。共享账务规则、SQLite 适配、桌面壳和 JSON CLI 已落地；移动端显示名称为“智账”，桌面端保留“简账”；工作区与包标识仍为 `ledger`。启动命令与当前限制见[开发说明](./docs/DEVELOPMENT.zh-CN.md)、[CLI 协议](./docs/CLI.zh-CN.md)和[验证记录](./docs/VERIFICATION.zh-CN.md)。

已确认的[白底视觉草稿](./design/nature-directions/fresh/index.html)正在接入共享客户端：悬浮底栏、简洁列表与弹窗、内置标签图标，以及“设置 → 外观 → 字体”中的本机字体偏好。验证记录分别说明构建结果与原生显示验收状态。

当前结论：纯本地、手动记账、可选标签、按账户盘点理财、支持信用卡、JSON 整本迁移，以及供外部 AI 调用的本地 CLI。首版不依赖账号、Supabase 或其他远程数据库。

## 1. 产品目标

做一个无广告、手动记录方便的个人记账与资产盘点应用。主要收入场景是工资，兼顾日常支出，以及现金、股票、基金和其他理财资产。

优先回答三个问题：本月收入多少、花了多少、现在总共有多少资产。录入操作尽量少，允许不填标签和备注；不要求用户补齐历史流水或维护完整证券交易记录。

目标平台为 Android、macOS 和 Windows，同期开发和验证，未来可能支持 iOS。第一版无需登录，离线可完整记账，各设备保存独立的本地账本，通过手动导出、导入在设备之间迁移。可向其他人分发 APK，每位安装者的数据独立，不会因此访问到其他人的账本。

| 功能    | 第一版设计                                                                   |
| ------- | ---------------------------------------------------------------------------- |
| 账户    | 手动创建现金、银行卡、微信余额、支付宝余额、信用卡等账户，填写期初余额或欠款 |
| 流水    | 支出、收入、账户间转账；支持补记、修改、删除                                 |

| 统计    | 本月收入、支出、结余；按日和标签查看支出；总资产、信用卡欠款和已记录净资产   |
| 盘点    | 输入实际余额或当前市值，保留校准与估值更新记录                               |

## 3. 手动记账与标签

记账入口先选“支出 / 收入 / 转账”，默认进入支出并显示金额键盘。

- 金额必填；账户必选，但沿用上次选择，通常无需再次操作。
- 标签与备注选填，不填写也能直接保存。
- 默认时间为现在，可以修改日期和时间补记。
- 标签点击选中，再点取消；常用项直接展示，“＋”进入更多标签或新建。
- 保存后给出明确反馈；编辑、删除入口放在流水详情。

金额输入与其他字段分开组织，进入时直接聚焦金额；桌面支持键盘输入。默认账户来自用户上次选择，标签仍保持可选，不自动生成用户未确认的内容。保存期间阻止重复提交，失败时保留输入，便于修改或重试。Cashew 的金额输入和默认账户交互可作参考，具体实现仍按本项目的简化流程设计。

默认标签只是起步建议，最终名称可在界面评审时调整：

| 类型 | 建议默认标签                         |
| ---- | ------------------------------------ |
| 支出 | 吃饭、交通、住房、买东西、娱乐、医疗 |
| 收入 | 工资、奖金、利息、其他收入           |

不同时设置“购物 / 日常 / 生活 / 日用”等边界重叠的标签。标签不设层级，收入与支出分别管理，转账不需要标签。删除标签前说明影响并确认：账目保留，相关流水变为“未标记”；隐藏则保留历史标签，只从快捷选择中移除。改名不改变金额或交易类型。

未标记的流水必须计入总额，统计中单独显示“未标记”，避免标签统计少算。

## 4. 资产与理财：先支持盘点

现金账户通过“期初余额 + 后续流水”计算余额。微信支付、支付宝支付只是支付渠道；如果实际扣的是银行卡，应记录到对应银行卡，不能再扣一次钱包余额。

投资按账户记录总额，例如“股票账户”“基金账户”“支付宝理财”。第一版不拆分每个产品和子持仓。支付宝余额与支付宝理财分开记录，理财总额不再包含已单独记录的余额；证券账户若填写含可用现金的总资产，就不能额外重复计入这部分现金。

第一版只要求填写初始估值，并在需要时更新当前总额；不填写证券代码、份额、成本和逐笔买卖。显示最后盘点日期，明确它是手动估算值。定投和每日申购限额不需要配置，也不按计划自动扣账。

银行卡转入理财账户、赎回到账按转账处理：来源减少、目标增加，手续费可单独记支出。转入后再按实际市值盘点。估值更新应替换当时的账面估值并记录差额，不能在转账已经增加金额后，再把新市值重复累加。第一版不计算卖出收益或区分已实现、未实现盈亏。

现金漏记可通过余额校准修正，投资涨跌通过估值更新反映；两者单独留痕，不伪装成工资或消费。校准也意味着收支流水可能不完整，不能据此声称每笔支出都已记录。

如果定投频繁且不想逐笔记转账，可以定期在同一次盘点中核对银行卡与理财账户的实际金额。已知的实际转入、转出可按周期汇总补记一笔转账，再校准剩余差额；若只知道两边余额，就分别校准并标记为“盘点差额”，不根据余额差额猜测投资收益。漏记或待确认的投资扣款不能自动变成消费支出。现金和投资的盘点日期不同，汇总资产只能作为近似值。

## 5. 信用卡：消费记一次，还款记转账

信用卡账户记录当前欠款，不把授信额度计入资产。期初欠款作为起始负债，不重复计入本月消费。

| 操作（合成示例）     | 收支统计         | 账户变化                                 |
| -------------------- | ---------------- | ---------------------------------------- |
| 信用卡消费 100 元    | 支出增加 100 元  | 信用卡欠款增加 100 元，银行卡不变        |
| 银行卡还款 100 元    | 不再记支出       | 银行卡减少 100 元，信用卡欠款减少 100 元 |
| 信用卡消费退款 20 元 | 冲减原消费 20 元 | 信用卡欠款减少 20 元，不记普通收入       |
| 利息或手续费         | 单独记费用支出   | 按实际扣款账户减少余额或增加欠款         |

支持部分还款。账单日、还款提醒、分期计划和额度管理暂不实现；发生分期时仍以消费时记一次支出、本金还款记转账、利息记费用为原则。信用卡溢缴款应显示为自有资金，避免把它当成负欠款重复计算。

## 6. 统计口径

- 本月收入：本月已记录的收入，包括工资等；期初余额不算收入。
- 本月支出：本月已记录的消费及费用；账户转账、投资转入不算支出。
- 本月结余：已记录收入减已记录支出，不等同于账户余额或总资产变化。
- 总资产：现金账户余额加投资最新估值，避免重复计入。
- 已记录净资产：总资产减已记录负债，第一版包括信用卡欠款；若有未录入的其他负债，数字不代表完整财务状况。
- 余额校准和估值变化单独展示，不混入日常收支。收支按交易发生时间和约定的账本时区归属月份。

第一版默认人民币，其他借款和多币种以后按需要扩展。退款冲减关联的原支出，支持部分退款，在退款发生的月份减少支出，不作为普通收入。某个月只有退款时，支出可以为负数。

## 7. 页面与多端体验

- 总览：本月收入、支出、结余，当前总资产、欠款和已记录净资产，以及最近流水。
- 明细：按日期分组，查看、筛选、修改和删除流水；从统计进入对应明细。
- 记一笔：始终容易找到的主要操作，金额优先，标签与备注选填。
- 资产：账户余额、投资估值、信用卡欠款与还款、转账、余额校准和估值更新。
- 设置：标签管理、备份与恢复等低频操作。

手机优先单手快速输入，桌面提供键盘输入和更宽的列表布局。具体导航数量和布局通过界面草稿确认，不要求各端布局完全一致。

## 8. 工程结构与技术建议

继续放在 `le-app/ledger/`，按同一产品组织多端。当前工程结构：

```text
ledger/
├── apps/
│   ├── client/       # Expo：Android，预留 iOS；Web 输出可供桌面复用
│   ├── desktop/      # Tauri：桌面壳与原生能力
│   └── cli/          # macOS / Windows 本地命令行入口
├── packages/
│   ├── core/         # 金额、流水、标签、账户、资产统计规则
│   └── storage/      # 存储接口、数据库迁移及平台适配
├── README.md
├── README.zh-CN.md
└── package.json      # ledger 内部 workspace，独立于其他产品
```

建议移动端采用 React Native + Expo，桌面采用 Tauri，本地采用 SQLite。共享业务规则和数据格式，文件访问、数据库驱动等按平台适配。桌面复用 Expo Web 界面作为候选方案，正式选型前验证导出、路由及存储适配。依赖版本按启动开发时的官方兼容要求确定。

账务金额使用整数最小货币单位，写入流水与更新关联账户应原子完成。期初余额、收支、转账、校准、估值分别建模；保留稳定 ID、数据版本和迁移机制。暂不为未确定的功能建立空包或复杂框架。

具体遵循以下约束：

- 共享业务层提供新增收支、修改流水、转账、退款、盘点、统计和备份恢复等入口。手机、桌面和 CLI 调用同一套入口，不在各界面分别更新余额。
- 业务层依赖明确的存储与文件接口；SQLite 驱动、平台文件选择和分享由适配层实现。业务规则不依赖 React 页面、Tauri 窗口或 CLI 参数解析。
- 转账对外是一笔业务操作，包含来源、目标和金额；内部关联的两边必须一起新增、修改或删除，并在同一数据库事务内提交。界面不让用户独立编辑转账的半边，信用卡还款复用同一规则。
- 余额与统计由期初、有效流水和盘点记录计算。可以缓存结果，但缓存应可重建；补记、修改、删除旧账后重新计算受影响的余额和统计，避免与界面保存的余额各自演化。
- JSON 迁移、CLI JSON 返回和内部数据库分别保留版本边界。导出读取同一个一致性快照，不能混入一笔转账提交到一半时的数据；恢复后保留记录 ID 和关联关系。

导出采用完整 JSON 账本，包含格式版本、账本 ID、账本名称、导出时间，以及账户、标签、流水、盘点记录和必要设置；不包含设备凭据和签名材料。CSV 无法完整保留关联关系，不作为首版恢复格式。若提供明文 JSON，导出界面必须说明文件可被读取；加密导出的具体方式仍需在实现前确定，不将普通 JSON 宣称为加密备份。

导入时先校验格式、版本、金额和引用关系，展示账本名称、导出时间与记录数量，明确告知替换范围，经确认后替换本地整本账。导入前自动保留本地备份，校验或写入失败不得破坏原账本。重复导入同一文件不会追加或复制流水；不支持的未来格式版本应拒绝导入，不能静默丢字段。

首版的“手动 JSON 同步”准确含义是整本账迁移，既不自动合并，也不自动判断哪一端最新。换设备前从当前最新账本导出，在目标设备导入后继续记录；同一时间以一端为准，不要在两个独立副本上同时记账后相互覆盖。导出时间仅帮助辨认文件，不能证明它包含另一端的全部修改。

手动[局域网传输](./docs/LAN_TRANSFER.zh-CN.md)复用同一格式：桌面开启一次性加密连接，手机选择覆盖方向，接收方明确确认后自动备份原账本再整本替换。云同步和双向合并仍需另行设计。

## 9. AI 接入：本地 CLI 优先

先提供稳定、可被不同 AI 工具调用的命令行接口；Skill 负责说明如何调用，不能替代实际接口。CLI 首版运行于 macOS、Windows，直接操作该电脑的本地账本，不启动公网服务、不需要登录。Android 账本可经 JSON 迁移到电脑后再操作；CLI 修改不会自动同步回手机。

CLI、手机界面和桌面界面共用账务规则；CLI 通过相应平台的存储适配访问同一本账，不另建一份独立数据库，不让 AI 绕过业务规则直接修改 SQLite。

命令职责（当前 CLI 使用这些分组查询，写操作统一使用 `apply --stdin`，具体见协议说明）：

| 命令组                              | 能力                                                             |
| ----------------------------------- | ---------------------------------------------------------------- |
| `ledger accounts` / `ledger labels` | 查询、创建和修改账户及标签                                       |
| `ledger transactions`               | 按时间、账户、标签筛选明细；新增、修改、删除单笔收支             |
| `ledger apply --stdin`              | 按共享命令格式执行账户/标签变更、收支、原子转账/还款、退款与盘点 |
| `ledger assets`                     | 查询资产与欠款；提交余额校准或投资总额盘点                       |
| `ledger reports`                    | 查询月度收支、标签汇总、总资产及已记录净资产                     |
| `ledger backup`                     | 导出和导入完整 JSON 账本，遵守相同的备份与替换规则               |

接口要求保持简单但可靠：

- 提供帮助及接口版本；支持 JSON 输入输出，结构化输入可经标准输入传递；错误有明确错误码和进程退出码。
- 查询支持筛选与分页，汇总返回时间范围、统计口径和估值日期；AI 解释分析以程序计算结果为依据，可按 ID 回查明细。
- 写入返回稳定记录 ID；金额使用整数分、账户和标签使用明确 ID。支持预演写入效果，模型补填不得伪造不存在的账户或交易事实。
- 新增、转账和盘点支持幂等操作 ID，AI 重试不能重复记账；修改或删除校验记录版本，拒绝覆盖桌面界面或其他 CLI 进程刚提交的新修改。
- 桌面与 CLI 同时访问时使用一致的事务与写入协调机制；整本导入需独占维护，忙碌或失败时明确返回，不留下部分替换的数据。
- 写入保留本地变更记录，注明来源为 CLI，便于在应用中核对；删除和整本替换提供预览及明确执行选项，自动化脚本不依赖交互弹窗。

后续可提供配套 Skill，说明账本选择、命令、金额单位、账务规则及常见操作；若需要 MCP，再在同一套业务接口上增加适配，不重新实现账务逻辑。当前已实现 CLI，未内置模型或 MCP 服务。

本地接口不会主动上传账本，但调用它的 AI 若使用远程模型，命令返回内容可能进入该模型的上下文。只查询任务需要的数据，避免默认导出整本账给模型；本地调试日志也不复制账目详情。账目备注和标签属于待分析的数据，不能作为让 AI 执行额外命令的指令。

## 11. 隐私与实施顺序

遵守仓库根目录的公开仓库指引。代码、文档、测试和截图只用合成数据；真实账目、余额、持仓、备份、数据库、Key 与签名材料不进入 Git。数据默认写入平台应用数据目录，运行时隐私数据与源码分开；必要的本地导出目录加入忽略规则。日志不输出账目详情或凭据，备份恢复需校验格式并在覆盖前提示。

按以下顺序实施，当前优先跑通 Android 本地记账：

1. 评审五张页面草稿：总览、明细、记一笔、资产、设置。五页一起确认导航和基本交互，先以 Android 记账闭环验证，共享结构兼顾桌面。
2. 实现共享账务规则与本地存储，贯通账户、支出、收入和转账。
3. 接入可选标签、信用卡、资产盘点和统计。
4. 完成 JSON 导出、导入前备份、失败回滚，以及三端安装与验证。
5. 基于同一套规则完成桌面 CLI 的基础读写与统计，验证它与界面显示一致、重试不重复记账。

首版验收重点：

- 无网络可完整操作；金额输入失败时保留草稿，连续点击保存不重复记账。
- 转账新增、改金额、换账户、删除时两边一致，总资产不会因内部转账变化；信用卡还款不重复计支出。
- 修改旧账后余额与统计一致；未标记账目仍计入统计；盘点不产生虚假收入。
- 三端导出、恢复后记录、关联及统计一致；坏文件、重复导入及中断导入不会丢账或重复记账。
- CLI 与界面结果一致，幂等重试和并发修改不导致重复或覆盖。
- APK 和其他安装包只包含空账本或明确的合成演示数据。

已确认：纯本地，无需账号；JSON 手动迁移整本账，不自动合并；理财按账户总额定期盘点；首版支持信用卡，消费记一次支出、还款记转账；Android、macOS 与 Windows 同期开发；桌面本地 CLI 支持外部 AI 读写和分析；独立 Web 版和 iOS 后置。后续界面评审再细化默认标签、盘点入口、跨月退款展示和备份加密方式。
